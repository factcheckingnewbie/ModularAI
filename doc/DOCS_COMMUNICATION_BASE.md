# Documentation & Communication Guidelines for ModularAI

This file serves as a base for discussing, planning, and implementing documentation strategies for the ModularAI project.
Use this as a reference when working with other AI assistants or collaborators to avoid mixing documentation process discussions with technical planning.

---

## 1. Purpose

- Ensure clarity on what documentation is needed at different project stages.
- Prevent confusion or overlap between technical planning and documentation process discussions.

---

## 2. Documentation Process

### a. Core Principles
- Documentation should be concise, clear, and relevant to the intended audience (users, developers, or admins).
- Separate "how-to" (user-facing) docs from "why/how it works" (developer-facing) docs.
- Use Markdown for all documentation files for portability and readability.

### b. Essential Documentation Types
- **README.md**: Project overview, setup, and usage.
- **BROADPLAN.md**: High-level development roadmap and milestone tracking.
- **MODULE_GUIDE.md**: How to develop, configure, and connect modules.
- **CONFIG_SCHEMA.md**: Reference for configuration file structure and options.
- **TROUBLESHOOTING.md**: Common issues and solutions.
- **CHANGELOG.md**: Track major changes and releases (optional but recommended).
- **DOCS_COMMUNICATION_BASE.md**: This file; for communication about documentation.

### c. Collaboration Guidelines
- Before making major documentation changes, communicate intent using a dedicated discussion or issue (not mixed with technical planning).
- When working with an AI, provide or reference this file to clarify the context and scope of documentation-related interactions.

### d. Versioning and Maintenance
- Each doc should include a last-updated date and a brief changelog if changed significantly.
- Outdated docs should be flagged for review in a visible way (e.g., a notice at the top).

---

## 3. Minimal Documentation System (Recommended)

To keep the project moving forward, maintain at least:
- Up-to-date **README.md**
- High-level **BROADPLAN.md**
- **MODULE_GUIDE.md** for module developers

Optional but helpful:
- **CONFIG_SCHEMA.md**
- **TROUBLESHOOTING.md**
- **CHANGELOG.md**

---

## 4. Communication with Other AIs

- Always reference this file when starting documentation discussions with another AI or system.
- Keep these discussions in separate channels (or files) to avoid cluttering technical design threads.
